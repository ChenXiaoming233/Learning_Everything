# 算法

## 贪心

> for循环从头到尾只跑一次
>
> 往往只比较相邻两数
>
> ~~逻辑偶尔简单地令人发指~~

“每一步都做出当前看来最优的选择，最终得到的解也是全局最优。”

**贪心不可回退！**



### 判断贪心可行的两个关键条件

#### 贪心选择性质

能通过每一步的“局部最优”选择构造出最终的最优解。

也就是说，题目的最优解可以分解为若干个局部最优决策的组合。

*举例：活动选择问题*

- 目标：选出最多的不重叠活动。
- 贪心策略：每次选结束时间最早的活动。
- 为什么可行？因为选择最早结束的活动不会影响之后能选的活动数量，是局部最优，也是通往全局最优的关键。

#### 最优子结构性质

全局最优解可由一系列局部最优选择组成。

这点和动态规划相同——但区别在于：

- **动态规划**：问题有“重叠子问题”，而贪心每次的选择是**唯一且不可回退**的。

- **贪心**：只要当前做出最佳选择，就不必考虑其他路径。

  

### 判断流程

| 步骤 | 判断内容                           | 问题的信号                                     |
| ---- | ---------------------------------- | ---------------------------------------------- |
| 1️⃣    | 是否存在一种“选择”可以逐步构造解？ | 问题可以**分阶段**做决策（如排序、选取、分配） |
| 2️⃣    | 每一步的最优选择是否不会影响未来？ | 局部选择**独立**，不会破坏后续可行性           |
| 3️⃣    | 能否证明局部最优可导出全局最优？   | 通常可用“交换论证法”证明                       |
| 4️⃣    | 是否无需回溯或记忆状态？           | 如果需要考虑前后状态或组合，可能要用DP         |



### 贪心题常见的题型信号

✅ 典型可贪心题：

| **类型**            | **典型题目/示例**                             | **贪心核心思想**                 | **为什么贪心可行（性质说明）**                               |
| ------------------- | --------------------------------------------- | -------------------------------- | ------------------------------------------------------------ |
| **区间类问题**      | 活动选择问题、区间覆盖问题                    | 选“结束最早”或“能覆盖最远”的区间 | 每次选择局部最优区间（留出最大剩余空间）不会破坏后续最优性，具备贪心选择性质 |
| **排序/构造类问题** | 哈夫曼编码、最小字典序排列                    | 局部排序优先、每次合并最小元素   | 合并代价单调、每次局部最优能递归构成全局最优结构             |
| **分配类问题**      | 最小硬币找零（面值成倍关系，如1,5,10,50,100） | 每次尽量取最大面值               | 面值体系满足“贪心安全性”（即子问题最优不受前一步影响）       |
| **图论构造问题**    | Kruskal / Prim 最小生成树                     | 每次取当前最小边但不成环         | MST 具有最优子结构 + 贪心选择性质，局部最小扩展不影响全局最优 |
| **最短路径问题**    | Dijkstra 算法（非负权图）                     | 每次确定当前距离最小的未访问节点 | 距离非负保证已确定的最短路径不会被改进，局部确定即全局最优   |
| **覆盖/选择问题**   | 区间覆盖最少点、最少区间覆盖                  | 每次选当前能“延伸最远”的区间     | 局部最优的延展最大化全局可行区间数，满足贪心选择性质         |
| **组合构造问题**    | 哈夫曼树、最优合并问题                        | 每次合并两个最小代价节点         | 局部合并最小化当前代价总和，最终代价最小                     |



❌ 不适合贪心的典型信号

- 某一步的选择会**影响后续的可行性**。
- 存在多种路径，必须保存所有可能路径的最优结果进行比较与更新（如背包问题、区间DP）。
- 局部最优并不唯一，且不同选择影响最终结果（如子序列问题）。

| 题型                                    | 示例                              | 为什么贪心不可行                               |
| --------------------------------------- | --------------------------------- | ---------------------------------------------- |
| **0/1 背包问题**                        | P2392、经典背包题。               | 局部选“性价比最高”的物品不一定能组合出最优解。 |
| **子集和接近问题（Partition Problem）** | P2392 就是这种。                  | 局部最优（先放最大）可能阻断后续更优组合。     |
| **最长上升子序列（LIS）**               | 数组中找最长递增序列。            | 需要全局状态转移，局部最长不代表全局最长。     |
| **图中含负权的最短路径**                | Bellman-Ford 必须比较所有边松弛。 | Dijkstra 贪心假设不再成立。                    |
| **背包中带有依赖或组约束**              | 如“选这件必须选那件”。            | 贪心无法处理依赖约束。                         |
| **调度优化（如机器负载平衡）**          | 多台机器分任务。                  | 局部“放最短任务”不保证全局最优平衡。           |



## 二分查找

### 特征

- 单调性
- **数据范围大** 

## 二分答案

### 特征

- 求最大/最小值;

- 答案离散(答案有有限种可能);

- 容易判断答案是否正确(事实上,这题如果要写SPJ,只需要满足ans满足条件但ans+1不满足条件即可)。

## 区别

✅ 二分查找是「我知道序列有序，我要找某个值」，在**一个有序序列**中查找**某个具体值或位置**。
✅ 二分答案是「我不知道答案，但我知道如果给出一个值，我能较为简易地判断它‘是否可行’」，在**答案的可能范围**内查找**满足某种条件的最优值**。





## 回溯算法与 DFS

与贪心相比，递归是**穷举所有可能**（逐层尝试该层的每种可能），遇到不合法的结果立即回溯（在每层都维护当前状态）：

- 对每个项，考虑其所有状态；
- 递归展开，就能枚举出所有可能；
- 在所有合法子集中选择最优解；

递归三要素：**状态、选择、回溯**

- **状态**：由全局变量 `x`（当前考虑的作业索引），`nowtime`（当前已选作业总耗时），还有外部的常量 `sum`、`maxdeep` 决定。
- **选择**：对于索引 `x`，有多条路径可以选择
- **回溯**：选了就将 `nowtime += a[x]`，递归回回溯后要利用传参或 `nowtime -= a[x]` 恢复现场；不选则直接递归，不需要恢复。

#### 回溯控制：全局变量与参数传递

- 全局变量：固定结构（P1605 迷宫），频繁修改且大数据量
- 参数传递：组合 / 子集问题（P2392 选题，P1036 选数），数值状态累加问题（选与不选）（P2036 PERKET）

### 特征

树状的可能结果，枚举排序

### 技巧

排序：将待递归的数组进行排序，令其能够更快地触发剪枝；

参数传递回溯的参数选择：传递的参数信息必须足够做出决策，在下一层递归仍然需要，且在当前层可能变化；位置状态（第几项、树节点、棋盘位置）(idx)，累计状态（当前和、已选数）(now)，问题依赖状态（限制条件、目标值）(sum)

### 注意

不选的分支不代表什么都不改变 (idx + 1)

递归中**绝不能写 ++**，自增自减运算符会改动变量原有的值 (P1036)

更新答案时注意若取 **min()**, 则 ans 应为 **INT_MAX** 而非 0, 否则始终为最佳答案无法更新 (P2036)



### 题型

#### 元素可重复

元素重复时，需要防止 **同一层循环中 **选择 **相同值的元素** 生成 **重复** 子序列

##### 方法一：排序

1. 在 **主函数** 中排序，让相同的元素靠在一起

   

   ```cpp
   sort(nums.begin(), nums.end());
   ```

2. 在 **回溯** 中剪枝

   - **无序** 集合：对于值相同的相邻树枝只遍历第一条，以避免重复

     ```cpp
     // ! 注意 i > start 不可少，将剪枝限制在同一层中
     if (i > start && nums[i] == nums[i - 1]) // 若与前序元素相同，则跳过该分支
         continue;
     ```

   - **有序** 排列：保证相同元素在排列中的相对位置保持不变，以获取 `2 -> 2' -> 2''` 的无重复全排列结果

     ```cpp
     // ! 注意 i > 0 不可少
     // 如果前序相邻的相等元素没有用过，则跳过；保证 2' 只在 2 已被使用时才被选择，2'' 只在 2' 已被使用时才会被选择
     if (i > 0 && nums[i] == nums[i - 1] && used[i - 1] == false)
         continue;
     ```

##### 方法二：`levelUsed` 哈希集合记录值

使用 `pathUsed` **哈希集合**标记，记录的是 **值** 而非元素

1. 在 **回溯** 中创建与初始化，是 **每层递归独立的临时集合**

   ```cpp
   void backtrack(vector<int>& nums, int start, vector<bool>& pathUsed) {
       unordered_set<int> used;
       ...
   }
   ```

2. 在 **回溯** 的 **剪枝** 中判断

   ```cpp
   for(int i = 0; i < nums.size(); i++) {
       if(pathUsed[i]) continue;
   
       // 当前层已选择过这个 **值** → 跳过
       if (levelUsed.count(nums[i])) continue; // 表示 levelUsed 中是否有 nums[i] 这个值
   
       // 标记
       pathUsed[i] = true;
       used.insert(nums[i]);
       track.push_back(nums[i]);
   
       backtrack(nums);
   
       // ! 注意 回溯时不需要擦除 levelUsed，它的作用域结束就自动销毁了
       track.pop_back();
       pathUsed[i] = false;
   }
   ```



#### 元素复选

防止同一个元素在 **同一条路径** 上重复出现（不可复选）

##### 在子列 / 组合（无序）问题中：使用 `start` 参数

子列 / 组合问题中，元素可以选也可以不选，顺序重要性不高，**但索引不能倒退**

1. 保证元素之间的相对顺序不变
2. 在 `backtrack()` 中使用 `start` 参数控制遍历的起始位置，
   - 令下一层遍历在 **` i + 1`** 开始，同一元素 **避免** 复选 且 **避免**重复组合（元素相同顺序不同）
   - 令下一层遍历在 **` i`** 开始，同一元素 **可** 复选 且 **避免**重复组合
   - 令下一层遍历在 **` 0`** 开始，同一元素 **可** 复选  且 **可** 重复组合

##### 在排列（有序）问题中：`pathUsed`数组记录元素下标

使用 `pathUsed` 数组标记 **元素下标**：排列问题中，元素相同顺序不同是正常现象，无需避免；有序排列也无法令元素相对位置固定，不适用 `start` 去重

1. 在 **主函数** 中创建与初始化，是 **随递归路径累积的全局状态**

   ```cpp
   vector<vector<int>> findSubsequences(vector<int>& nums) {
       int n = nums.size();
       vector<bool> pathUsed(n, false); // 标记当前路径上下标是否已使用
       backtrack(nums);
       return res;
   }
   ```

2. 在 **回溯** 的 **剪枝** 中判断

   ```cpp
   for(int i = 0; i < nums.size(); i++) {
       // 当前路径已选择过这个 **元素** → 跳过
       if(pathUsed[i]) continue;
   
       if (levelUsed.count(nums[i])) continue;
   
       // 标记
       pathUsed[i] = true;
       used.insert(nums[i]);
       track.push_back(nums[i]);
   
       backtrack(nums);
   
       track.pop_back();
       pathUsed[i] = false;
   }
   ```



#### 一些实际情况

##### 子集 / 组合（无序）+ 元素无重不可复选

为保证不可复选 且 不重复（元素相同顺序不同）：

1. 保证元素之间的相对顺序不变
2. 在 `backtrack()` 中使用 `start` 参数控制遍历的起始位置，令下一层遍历在 **` i + 1`** 开始，令同一元素 **避免**复用 且 **避免**重复组合

##### 排列（有序）+ 元素无重不可复选

为保证不复选 且 不重复：

1. 使用 `pathUsed` 数组标记：排列为有序，无法令元素相对位置固定，不适用 `start` 去重



##### 子集 / 组合（无序）+ 元素可重不可复选

为保证不可复选 且 不重复（元素相同顺序不同）：

1. 保证元素之间的相对顺序不变
2. 在 `backtrack()` 中使用 `start` 参数控制遍历的起始位置，令下一层遍历在 **` i + 1`** 开始，令同一元素 **避免**复用 且 **避免**重复组合

1. 使用 `pathUsed` 数组标记：排列为有序，无法令元素相对位置固定，不适用 `start` 去重

1. 在主函数中排序，让相同的元素靠在一起


2. 在回溯中剪枝，由于元素可重，故保证相同元素在排列中的相对位置保持不变，以获取 `2 -> 2' -> 2''` 的无重复全排列结果

1. 保证元素之间的相对顺序不变

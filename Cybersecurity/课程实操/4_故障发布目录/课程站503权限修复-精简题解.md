# 课程站 503 权限修复题解

## 一、题目考点

本题主要考查 Linux 文件系统权限及其在 Web 服务部署场景中的应用，包括：

1. 使用 `cat` 读取服务配置，确认发布目录、服务账号、服务组和敏感文件；
2. 使用 `namei -l` 检查发布路径上每一级目录的穿越权限；
3. 使用 `find -ls` 检查发布目录中各文件和目录的权限、属主及属组；
4. 理解目录执行权限 `x` 对路径穿越的作用；
5. 使用 `chmod` 和 `chown` 修复目录、普通文件及敏感文件；
6. 遵循最小权限原则，避免向无关用户开放写权限；
7. 为敏感部署文件设置比普通网页文件更严格的权限；
8. 在不修改、删除或替换网页内容的前提下恢复站点服务。

## 二、解题思路

### 1. 连接题目终端

使用平台提供的 SSL 连接命令：

```sh
ncat --ssl pwn-58007eef87.adworld.xctf.org.cn 9999
```

连接成功后，查看终端允许使用的命令及 `find` 语法：

```sh
help
help find
```

### 2. 读取站点配置

执行：

```sh
cat /etc/campus-site.conf
```

得到：

```ini
document_root=/srv/releases/release-vvyrmgiws6/public
service_user=deploy
service_group=web
sensitive_file=.deploy-token
```

由此确认：

- 发布目录：`/srv/releases/release-vvyrmgiws6/public`
- 服务账号：`deploy`
- 服务组：`web`
- 敏感文件：`.deploy-token`

### 3. 检查路径及发布文件

使用 `namei` 检查发布路径上的每一级目录：

```sh
namei -l /srv/releases/release-vvyrmgiws6/public
```

使用 `find` 查看发布目录内的权限和属主：

```sh
find /srv/releases/release-vvyrmgiws6/public -ls
```

检查发现以下异常：

- `/srv/releases` 权限为 `700`，服务组 `web` 无法穿越；
- 版本发布目录权限为 `711`，向无关用户开放了执行权限；
- `assets` 目录权限为 `700`，服务组无法正常读取资源；
- `.deploy-token` 权限虽然已经是严格的 `600`，但属主属组错误，为 `nobody:nogroup`；
- 普通网页文件已经是 `640 deploy:web`，无需修改内容。

### 4. 修复权限和属主

先修复发布路径上相关目录的权限：

```sh
chmod 750 /srv/releases
chmod 750 /srv/releases/release-vvyrmgiws6
chmod 750 /srv/releases/release-vvyrmgiws6/public/assets
```

再修复敏感部署文件的属主，并保持严格的 `600` 权限：

```sh
chown deploy:web /srv/releases/release-vvyrmgiws6/public/.deploy-token
chmod 600 /srv/releases/release-vvyrmgiws6/public/.deploy-token
```

修复后的权限原则如下：

| 对象 | 属主和属组 | 权限 |
| --- | --- | --- |
| 发布路径相关目录 | `deploy:web` | `750` |
| 普通网页和资源文件 | `deploy:web` | `640` |
| 敏感文件 `.deploy-token` | `deploy:web` | `600` |

其中：

- `750` 允许属主读、写、进入目录，允许服务组读取和进入目录，不向其他用户开放权限；
- `640` 允许属主读写、服务组只读，且不向其他用户开放权限；
- `600` 仅允许属主读写，满足敏感文件权限必须严于普通网页文件的要求。

整个修复过程只修改文件系统权限和属主信息，没有修改、删除或替换任何网页内容。

执行：

```sh

```

检查通过：

```text

```
